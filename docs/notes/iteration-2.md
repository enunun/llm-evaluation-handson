# Iteration 2のノート

Iteration 2で初めて使う概念とライブラリをまとめる．
REPLの例は，演習パッケージのディレクトリで，依存を加えたあとに`node`を起動して試せる．

## 評価のスコアは推定値である

スイートのタスクは，製品が出会いうる問い合わせ全体からの標本である．
タスクを選び直せば，同じ製品でも合格率は変わる．
試行をやり直しても変わる．
評価で得た合格率は「真の合格率」の推定値であり，どの程度確かかを一緒に示す必要がある．

## 標準誤差と中心極限定理

値`x1, …, xn`の平均の標準誤差は，標本標準偏差`s`を`√n`で割ったものである．
中心極限定理により，平均は真の値を中心とする正規分布に近づく．
そのため，平均±1.96×標準誤差の範囲が，95%信頼区間になる．

95%信頼区間とは，同じ手順で何度も評価したとき，そのうち約95%の区間が真の値を含む，という意味である．
「真の値が95%の確率でこの区間にある」という意味ではない．

1.96は，標準正規分布で上側2.5%を切る点(97.5%点)である．

```text
> await import("@stdlib/stats-base-dists-normal-quantile").then(({ default: q }) => q(0.975, 0, 1))
1.9599639845400538
```

## 試行は独立ではない：タスクを単位にする

Iteration 1の振り返りで，qwen2.5:0.5bの評価(11タスク×10回)のpass@1は0.55だった．
110回の試行を独立とみなすと，標準誤差は`√(p(1 - p) / n)`で求まる．

```text
> Math.sqrt(0.55 * 0.45 / 110)
0.047434164902525694
```

しかし，同じタスクの10回の試行は同じ入力を使うため，結果が似る．
実際，`refund-01`は10回とも合格し，`shipping-01`は10回とも不合格だった．
10回の試行は，10個の独立な情報ではない．
タスクごとの合格率を1つの値とし，11個の値の標準誤差を求めると，3倍近く大きくなる．

```text
> await import("simple-statistics").then(({ sampleStandardDeviation }) => sampleStandardDeviation([1, 1, 0.5, 0, 0.5, 1, 1, 0.1, 0, 0, 1]) / Math.sqrt(11))
0.1390641685525305
```

このように，互いに似た観測のまとまり(クラスタ)を単位にして標準誤差を求めることを，クラスタ化という．
E. Millerの"[Adding Error Bars to Evals](https://arxiv.org/abs/2411.00640)"は，よく使われるベンチマークでもクラスタ化した標準誤差が素朴な見積もりの3倍を超えうることを報告している．
同じ論文は，同じ問題を何度か試行してその平均を使うと，問題ごとの揺れによる分散が減ることも述べている．
このコースの`--repeat`とタスクごとの平均は，この2つの勧めに沿っている．

## 二項分布とClopper-Pearson区間

1つのタスクを`n`回試行し，各試行が確率`p`で合格するとき，合格数は二項分布に従う．
合格数から`p`の区間を求める方法はいくつかある．

- 正規近似(Wald)：`p̂ ± 1.96 × √(p̂(1 - p̂) / n)`．`p̂`が0か1だと幅が0になり，10回中10回の合格で「100%で確実」と言ってしまう．
- Clopper-Pearson法：二項分布から正確に求める．幅は広めだが，含むべき確率を下回らない．

`@stdlib/stats-binomial-test`の`ci`は，Clopper-Pearson法の区間である．

```text
> await import("@stdlib/stats-binomial-test").then(({ default: test }) => test(10, 10).ci)
[ 0.6915028921812392, 1 ]
> await import("@stdlib/stats-binomial-test").then(({ default: test }) => test(7, 10).ci)
[ 0.3475471499400027, 0.9332604888222655 ]
> await import("@stdlib/stats-binomial-test").then(({ default: test }) => test(70, 100).ci)
[ 0.6001853238201958, 0.7875935795104633 ]
```

10回中10回の合格でも，真の合格率が0.69程度である可能性は否定できない．
試行を10倍にすると，区間の幅はおよそ`1 / √10`に狭くなる．

`binomialTest(x, n, { alpha })`の`alpha`は，1から信頼水準を引いた値である．

## 目標の合格率と「判定不能」

QA4AIのガイドラインのCustomer Expectationの節は，ある自治体の生成AIの実証実験の例を挙げている．
正答率を62.5%から94.1%まで上げたが，導入の条件を99.9%としていたため，導入を見送ったという．
目標は評価の前に決め，評価の結果と比べる．

1つの合格率ではなく区間と比べると，結果は3つになる．

| 結果 | 条件 | 意味 |
| --- | --- | --- |
| `met` | 区間の下限 ≥ 目標 | 目標を満たすと言える |
| `not met` | 区間の上限 < 目標 | 目標を満たさないと言える |
| `inconclusive` | それ以外 | どちらとも言えない．タスクや試行を増やせば決着しうる |

## ライブラリ

- `simple-statistics`：平均`mean`，標本標準偏差`sampleStandardDeviation`など，基本的な統計の関数を持つ．
- `@stdlib/stats-binomial-test`：二項検定．結果の`ci`がClopper-Pearson区間である．
- `@stdlib/stats-base-dists-normal-quantile`：正規分布の分位点`quantile(p, mu, sigma)`．`simple-statistics`の`probit`は近似の精度が低く，97.5%点が1.957になるため，こちらを使う．
