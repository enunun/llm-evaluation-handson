# Iteration 1のノート

Iteration 1で初めて使う概念，ツール，構文をまとめる．
REPLの例は，演習パッケージのディレクトリで`node`を起動して試せる．

## 非決定性の源

同じプロンプトを同じモデルに送っても，出力は変わりうる．主な源は次のとおりである．

- サンプリング：LLMは次のトークンの確率分布から1つを選ぶ．温度が高いほど，確率の低いトークンも選ばれやすい．
- 推論基盤：GPUの並列計算では，浮動小数点の足し算の順序が実行ごとに変わり，わずかな差が出力の分かれ目になることがある．同時に処理される他のリクエストとのまとめ方(バッチ)でも結果が変わる．
- モデルとランタイムの更新：同じ名前のモデルでも，版が変われば出力は変わる．

温度を0にすると，サンプリングの揺れは小さくなる．
それでも推論基盤や更新による揺れは残り，返信の下書きのように多様さが必要な機能では温度を下げられない．
評価では揺れを消すのではなく，揺れを含めた品質の分布を測る．

## 複数回の試行

promptfooの`--repeat <n>`は，各タスクを`n`回実行する．
結果JSONには試行ごとに1つの結果が入り，同じタスクの結果は同じ`testCase.description`を持つ．

```console
pnpm eval --repeat 10 -o results/fake.json
```

## pass@kとpass^k

タスクを1回試行して合格する確率を`p`とする．

- pass@k：`k`回試行して，少なくとも1回合格する確率．`1 - (1 - p)^k`．何度か試してよい場面での「能力」を表す．
- pass^k：`k`回試行して，`k`回とも合格する確率．`p^k`．顧客と直接やり取りする機能のように，毎回の成功が求められる場面での「一貫性」を表す．

`k = 1`では，どちらも合格率`p`に等しい．`k`が増えると，pass@kは1に，pass^kは0に近づく．

```text
> 0.8 ** 3
0.5120000000000001
> 1 - (1 - 0.8) ** 3
0.992
```

合格率0.8のタスクは，3回のうち1回でも合格する確率は0.99だが，3回とも合格する確率は0.51しかない．

### 試行の結果からpass^kを推定する

`n`回中`c`回合格したタスクのpass^kは，`n`回の試行から`k`回を選ぶ組み合わせのうち，すべて合格の試行だけを選ぶ組み合わせの割合`C(c, k) / C(n, k)`で推定する．
`(c / n) ** k`は真の値からずれた推定になるが，この式は偏りのない推定値になる．
掛け算の形`(c / n) × ((c - 1) / (n - 1)) × …`で計算すると，大きな数の階乗を作らずに済む．

```text
> (8 / 10) * (7 / 9) * (6 / 8)
0.4666666666666667
```

## stable，flaky，broken

ソフトウェアのテストで，同じコードで通ったり落ちたりするテストをflakyと呼ぶ．
このコースでは，タスクの全試行が合格ならstable，全試行が不合格ならbroken，合否が揺れればflakyと呼ぶ．
合格率が同じ0.7のスイートでも，flakyのタスクが多いのか，brokenのタスクがあるのかで，直し方が違う．
brokenはプロンプトや期待値の誤りを，flakyは指示のあいまいさや境界にある入力を疑う手がかりになる．

## シード付き擬似乱数

擬似乱数は，シードと呼ぶ初期値から決まった列を作る．同じシードからは同じ列ができる．
`@stdlib/random-base-mt19937`は，メルセンヌ・ツイスタという擬似乱数の生成器である．
`factory({ seed })`で生成器を作り，呼ぶたびに0以上`MAX`(2^32 - 1)以下の整数を返す．

```text
> await import("@stdlib/random-base-mt19937").then(({ default: mt19937 }) => { const g = mt19937.factory({ seed: 1 }); return [g(), g(), g.MAX]; })
[ 1791095845, 4282876139, 4294967295 ]
```

同じ式をもう一度評価しても，同じ列が返る．
`MAX + 1`で割ると，0以上1未満の数になる．

```text
> 1791095845 / (4294967295 + 1)
0.4170219984371215
```

シードは1以上2^32 - 1以下の整数でなければならない．

### 乱数を使うコードのテスト

乱数を使うコードは，シードを固定して決定的にしてから確かめる．
「noiseが0.2なら約2割が違う答えになる」のような性質は，固定したシードで十分な回数を試し，`toBeCloseTo`で確かめる．

### 並行に実行される試行の乱数

promptfooは複数の試行を並行に実行するため，プロバイダが呼ばれる順序は実行のたびに変わりうる．
1つの乱数の列を順に使うと，同じシードでも，どの試行にどの乱数が当たるかが変わってしまう．
そこで，シード，問い合わせ文，試行の番号から，試行ごとのシードを作る．
promptfooは，試行の番号を`callApi`の第2引数`context`の`repeatIndex`で渡す．

試行ごとのシードは，文字列から32ビットの整数を作るハッシュ関数FNV-1aで作る．
`Math.imul`は32ビット整数の掛け算，`>>> 0`は符号なし32ビット整数への変換である．

```text
> Math.imul(0x811c9dc5, 0x01000193) >>> 0
84696351
```

## 再現のための記録

評価の数字は，どのモデル，どのプロンプト，どのシードで得たかが分からなければ比べられない．
QA4AIのガイドラインのProcess Agilityの節は，乱数のシードなどの設定を記録し，同じ条件を再現できるようにすることを求めている．

promptfooのプロバイダは，応答に`metadata`を付けられる．付けた`metadata`は結果JSONの各結果の`metadata`に入る．

```ts
return { output: "refund", metadata: { llm: "fake", model: "keyword", promptVersion: "classify-v1", seed: 1 } };
```

プロンプトを変えたら版の名前も変え，どの版の結果かを区別できるようにする．

## `node:util`の`parseArgs`

コマンドライン引数を，オプションと位置引数に分ける．

```text
> await import("node:util").then(({ parseArgs }) => parseArgs({ args: ["summary", "r.json", "--k", "5"], allowPositionals: true, options: { k: { type: "string", default: "3" } } }))
{
  values: [Object: null prototype] { k: '5' },
  positionals: [ 'summary', 'r.json' ]
}
```

- `allowPositionals: true`で，オプション以外の引数を`positionals`に集める．
- 定義していないオプションが来ると，例外を投げる．
- 値は文字列で返るため，数に変えて検査する．
