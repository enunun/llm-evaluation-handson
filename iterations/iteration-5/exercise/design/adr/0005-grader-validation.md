# 0005 モデル型の採点器は，人手ラベルのTPRとTNRで検証してから使い，合格率を補正する

## 状況

Iteration 3で，LLM Judgeと意思決定モデルを採点器に加えた．
軽量なモデル(qwen2.5:0.5b)のJudgeは，方針を書き写しただけの返信も合格にした．その理由は，ルーブリックを書き写したものだった．
採点器の合格率がそのまま製品の品質を表すかは，採点器が正しく判定しているかによる．

## 決定

- 返信と，採点器ごとの人の判定を持つ人手ラベルのスイート(`labels.yaml`)を作る．各項目は`dev`か`test`の分割に属する．
- 人手ラベルのスイートを複数回評価し，採点器ごとに人の判定と比べる．混同行列，TPR(人が合格としたものを採点器も合格とした割合)，TNR(人が不合格としたものを採点器も不合格とした割合)，自己一貫性を求める．TPRとTNRは，判定できた試行だけで求める．
- TPRとTNRがどちらも0.80以上の採点器を，使える(`usable`)とする．使えない採点器があれば，`calibrate`は終了コード1を返す．
- ルーブリック，プロンプト，しきい値は`dev`で調整し，最後に`test`で確かめる．確率を返す採点器には，しきい値ごとのTPRとTNRを示す．
- 検証結果を使い，採点器が観測した合格率をRogan-Gladen法`(観測した合格率 + TNR - 1) / (TPR + TNR - 1)`で補正する．区間は，タスクの再標本化と，TPRとTNRの二項分布からの再標本化によるブートストラップで求める．

## 理由

- Anthropicは，モデルの採点器を人の採点者と照らし合わせて校正することを勧めている．H. Husainのvalidate-evaluatorは，人手ラベルをdevとtestに分け，TPRとTNRで採点器を測る手順を示している．
- 一致率(人と採点器の判定が同じ割合)だけを見ると，合格が多いデータでは「何でも合格」の採点器も高い値になる．人の判定が合格の側と不合格の側を別々に測る．
- ルーブリックやしきい値をラベルに合わせて調整すると，調整に使ったラベルでは良く見える．調整に使わない`test`で確かめると，その見かけの良さを見抜ける．作成時の環境では，tev1:0.8bのTPRは`dev`で1.00，`test`で0.67だった．
- 採点器の誤りは，観測した合格率を偏らせる．TPRとTNRが分かれば，その偏りを補正できる．補正は`TPR + TNR > 1`(採点器が当て推量より良い)のときだけ意味を持つ．

## 影響

- 人手ラベルを作る手間がかかる．Husainは100件程度(合格と不合格が半分ずつ)を目安にしている．このコースの20件では，率の区間が広い．
- 自己一貫性は，同じ項目の試行の結果がそろう割合である．低い採点器は，試行を増やして多数決をとるなどの工夫が要る．
- 補正の区間は，ラベルが少なく，TPRとTNRが低いほど広い．使えない採点器の補正値は参考にとどめる．
